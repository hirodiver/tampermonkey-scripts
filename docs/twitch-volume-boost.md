# Twitch Volume Boost について（ファイル: `twitch-volume-boost.user.js`）

> YouTube 版（`youtube-volume-boost.user.js`）と対になっている。片方を直したら、もう片方にも同じ直しを入れるかを提案する（CLAUDE.md「対になっているスクリプト」）。

Twitch の音量を **100% より上（最大 600%）** まで上げる。v1.1.0 から、見た目と操作を
[YouTube 音量ブースト](youtube-volume-boost.md) に揃えた。

プレイヤーの音量バーを、**つまみ1つで 0〜600% を動かせる1本の長いバー**に置き換える。
目盛りは**対数**で、0〜100% がバーの約 2/3 を占める（YouTube 版と同じ）。

```
[🔊][0 ── 25 ── 50 ── 100 │ 200 ── 400 ─ 600] 250%
     白（Twitch の音量）     オレンジ（増幅）
```

## 使い方

1. スピーカーアイコンにマウスを乗せると、長いバーが開く。左の約 2/3（白）が Twitch の音量 0〜100%、
   その右（オレンジ）が 100〜600%。クリック・ドラッグで1つのつまみのまま行き来できる。100% の近くでは 100% に吸い付く
2. バーの上で**ホイール**、フォーカスして **←→** でも動く（100% 以下は 5%、上は 10% ずつ）。
   Home で 0%、End で 600%。**バーをダブルクリックで 100% に戻る**
3. **プレイヤーの上で ↑↓ キー**を押すと、同じ刻みで 0〜600% を動かす（100% を超えると増幅）。
   画面上部に「音量 250%」が出る。チャット欄に入力中・プレイヤーの外では横取りしない
4. 100% を超えている間は、バーを閉じても右に「250%」がオレンジで出たままになる
5. **バーの右クリック**（または右の数字のクリック）で「きれい（リミッターあり）」と
   「大きく（リミッターなし）」が切り替わる。「大きく」では数字の後ろに `!` が付く
6. 増幅とモードは `GM_setValue`（キー `boostPercent` / `limiterOn`）に保存し、次回と別タブにも引き継ぐ
7. Tampermonkey のメニューにも「音量 +10%」「-10%」「100% に戻す」「きれい／大きく を切り替え」「診断をコンソールに出す」がある

v1.0 の「左上の ×1.00〜×5.00 のスライダー」と「Alt+↑ / Alt+↓ / Alt+0」は v1.1.0 で廃止した（要望）。
v1.0 で保存した倍率（キー `twitchBoost`、×2.5 など）は 250% として引き継ぐ。

## YouTube 版との違い

- **Twitch には YouTube の `getVolume` / `setVolume` のような窓口が無い。** 0〜100% の部分は、
  Twitch の音量バー（`input type=range`）の値を書き換えて `input` イベントを送り、
  人が動かしたのと同じように Twitch（React）に音量を変えさせる。ミュートを解くときはミュートボタンを押す
- Twitch の音量は、その音量バーの値（`min`〜`max` を 0〜100% に換算）、ミュートは `video.muted` で読む
- ↑↓ は「プレイヤーにフォーカスがある、または何にもフォーカスが無くマウスがプレイヤーの上にある」ときに受け取る。
  Twitch は動画をクリックしてもフォーカスが本文に残ることがあるため
- 設定は `localStorage` ではなく `GM_setValue`

## 作りの要点

- 音声経路は `video → MediaElementSource → GainNode → DynamicsCompressor（きれいのとき・100% 超の間だけ）→ destination`。
  リミッターのしきい値は YouTube 版と同じ 0dB（下げると Chrome が自動で音を持ち上げ、表示とずれる）
- **100% 以下なら音声に一切触らない。** 100% を超えたときに初めて `AudioContext` を作り、動画をつなぐ。
  一度つないだ動画は外せないため
- **自動再生の制限**: 操作前は Web Audio が止まっている。止まったままつなぐと**無音になる**ので、
  つながずに待ち、最初のクリックかキー入力で動き出してからつなぐ。待っている間は数字が薄くなる
- **MSE で再生している video（`srcObject` か `blob:`）だけをつなぐ。** 別オリジンの直接URL
  （iOS Safari のネイティブHLS等）をつなぐと CORS の制限で無音になるので、触らない
- **現行の Twitch は `src` が空で、`srcObject` で再生している**（実機の診断で確認、2026-11）。
  Amazon IVS Player がワーカーの MediaSource を `srcObject` で渡すため。
  v1.0.0〜v1.0.1 は `blob:` だけを見ていて、これを「読み込み前」と見なし、**一度もつながず増幅されなかった**（v1.0.2 で修正）
- Twitch 本来の音量バーは**消さずに見えなくする**（`visibility: hidden`）。音量を動かす窓口として使うのと、
  開いた幅を `ResizeObserver` で測って長さの基準・開くきっかけにするため。
  隠すのはこのバーがすぐ隣に付いているときだけなので、付け損ねても Twitch の音量バーは残る
- バーの長さは、Twitch の音量バーの実測幅（未計測なら 60px）からつまみの直径を引いた長さの 6 倍。
  プレイヤーの幅の 30% までに縮める
- プレイヤーは `.video-player__container`（実機で確認）→ `[data-a-target="video-player"]` → `.video-player` の順に探し、
  一番大きい video を持つもの（幅 300px 以上）を使う。サイドバーのプレビュー等には付けない
- Twitch の音量バーは `input[data-a-target="player-volume-slider"]` → `input[id^="player-volume-slider"]`（実機で確認）→
  `.volume-slider__slider-container input[type="range"]` の順に探す
- バーの置き場所: `.volume-slider__slider-container`（実機で確認）の直後 → 音量バーそのものの直後
  （ここまでは Twitch の音量バーを隠して置き換える）→ ミュートボタンの直後 → 左の操作列の末尾。
  Twitch の音量バーが見つからなければ、Twitch のバーを残して右に 100〜600% の延長部分（64px）だけを付ける
- 配信の切り替え・プレイヤーや音量バーの作り直しは `MutationObserver` で見て付け直す。
  新しい video も 100% 超ならつなぐ。バーは操作バーの中にあるので、全画面でもそのまま出る

## 効かないときは

コンソールで `__tmTwitchVolumeBoost.dump()`（またはメニューの「診断をコンソールに出す」）を実行すると、
診断が文字（JSON）で出る。コンソールの表示をそのままコピーして貼ればよい
（v1.0.0 は表で出していたため、コピーすると `Array(1)` に畳まれて中身が落ちた）。

- `state`: 音量・ブースト・増幅率・`AudioContext` の状態・リミッター・Twitch の音量・
  Twitch の音量バー（要素・`min` / `max` / `value`）とその入れ物・バーの形と長さ・設置先・つないだ動画の数
- `videos`: video ごとの大きさ・再生元（`srcObject:MediaSourceHandle` など）・つないだか・エラー・親6段のクラス名

`__tmTwitchVolumeBoost.set(300)` で直接変えることもできる（0〜600）。
Volume Master など、ほかの音量拡張と同時に使わない（倍率が重なる。動画を先につながれていると増幅できず、数字が赤くなる）。

## 検証

```
node --check twitch-volume-boost.user.js
NODE_PATH=$(npm root -g) node test/twitch-volume-boost.test.js
```

Twitch のプレイヤー（操作バー・ミュートボタン・ホバーで開く音量バー）を模したDOMに、
正弦波を鳴らす `<video>`（`src` が空で `srcObject` 再生に見せる）を置き、
**つまみの位置・Twitch の音量・スピーカーへ出ていく音の大きさ（`AnalyserNode`）を実測**する。
Twitch の動き（音量バーの `input` で `video.volume` を変える、ミュートボタン、video 側の変化で音量バーを描き直す）も真似る。
59項目（Twitch の音量バーを隠して置き換える／ホバーで開きプレイヤー幅の 30% に収まる／対数目盛り／
0〜100% は Twitch の音量で音声に触らない／300% で実際に 3 倍・100% で元どおり・40% で 0.4 倍／
ドラッグ・100% への吸い付き／ホイール・←→・Home/End・ダブルクリック／プレイヤーの上での ↑↓、
外やチャット欄では横取りしない／Alt+↑ は廃止／Twitch 側で音量を下げると増幅を外す／ミュートの表示と解除／
きれい・大きく（0.5 × 600% が 1 前後 / 3.0）／配信の切り替え・音量バーだけの作り直し／フルスクリーン／
JSON の診断／音量バーが無いときの延長部分／v1.0 の保存値の引き継ぎ／自動再生の制限中はつながず、クリック後に効く）を確認する。

模擬DOMのうち実機で確認済みなのは、`.video-player__container`、`input#player-volume-slider-…` とその入れ物
`.volume-slider__slider-container`、`srcObject` 再生の3点だけ。ミュートボタンの `data-a-target`・音量バーの
`min` / `max`・Twitch（React）が `input` イベントで音量を変えるかは推測なので、**実機確認の代わりにはならない**。
