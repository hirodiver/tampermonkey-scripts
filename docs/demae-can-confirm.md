# 出前館 到着確認 について（ファイル: `demae-can-confirm.user.js`）

カートで「注文を完了する」を押した後、混雑等で到着時刻が変わった場合にのみ出る
「お届け時間に変更があります」確認モーダル内の「注文を完了する」ボタンを自動でクリックする。

## 押す条件

注文を勝手に確定させないよう、次の3つをすべて満たすボタンだけを押す。

1. 利用者が自分で注文のボタン（文字に「注文」を含むもの）を押してから2分以内
   （`USER_CLICK_WINDOW_MS`）。スクリプトの `click()` は `isTrusted` が false なので数えない
2. 利用者が押した時点では画面に無かった「注文を完了する」ボタン。
   カート本体のボタンは押した時点で画面にあるので、作り直されない限り対象外になる
3. ボタンを囲むダイアログ（`role="dialog"`・`role="alertdialog"`・`aria-modal="true"`・`<dialog>`、
   または画面に固定された重ね表示）の中に「お届け時間」「変更」がある

非表示で差し込まれ、後から表示に切り替わるモーダルにも対応するため、要素の追加に加えて
`style`・`class` などの変化も監視している。

## v1.1.0 で直したこと

v1.0.x はボタンの祖先8段の文字に「お届け時間…変更」が含まれるかだけで判定していた。
そのため次の場合に、カート本体の「注文を完了する」まで自動で押していた。

- カート画面に「お届け時間：最短30分 [変更]」のような行がある
- 読み込んだ時点でモーダルが出ている
- モーダルの表示中に本体のボタンが作り直される

## 効かないとき

- 出前館側のDOM構造（文言・モーダルの作り）が変わると効かなくなる可能性がある。
- DevTools で `__tmDemaeConfirm.dump()` を実行すると、「注文を完了する」ボタンごとに
  表示中か・押した時点にあったか・囲むダイアログ・見出しが当たったかを表で出す。
  `dialog` が「（なし）」なら、モーダルがダイアログとして判定されていない。

## 検証

```
node --check demae-can-confirm.user.js
NODE_PATH=$(npm root -g) node test/demae-can-confirm.test.js
```

カート画面と確認モーダルを模したDOMで21項目を確認する。利用者のクリックは Playwright の
`page.click`（`isTrusted` が true）で再現する。出前館の実DOMではないので、実機確認の代わりにはならない。
