# X アカウント切替 について（ファイル: `x-account-switcher.user.js`）

画面端に、ログイン中のアカウントのアイコンを並べた小さな帯（ドック）を出す。
アイコンを押すと、X 本体の切替メニューを代わりに開いて該当アカウントを押す。
切替そのものは X 本体が行うので、非公式APIは叩かない。

Grok が作った「TapShift」（v1.1.0）を元に作り直したもの。

## 使い方

1. 初回はドックに「読込」ボタンだけが出る。押すと X の切替メニュー
   （iPhone では左上のアイコン → ドロワー → アカウント一覧）を開いて一覧を覚え、閉じる。
   X の切替メニューを自分で開いたときも、その場で覚える
2. 以後はドックのアイコンを押すだけで切り替わる。現在のアカウントには青い輪（X の青）が付き、押しても切り替わらない
   （押すと下の「更新」「大きく」「小さく」が出る。5. と 8. を参照）
3. タイムラインを下へ送ると、X の投稿ボタンと同じタイミング・同じ濃さでドックが薄くなり、
   戻すと濃く戻る（v1.8.0。投稿ボタンの濃さを読み取って写している。読める濃さ 0.35 より薄くはしない。
   v1.8.1 からはスクロールのたびには計算せず、X が投稿ボタンの濃さを変えたときだけ追う）
4. 切替後は、ホームの「フォロー中」タブを開く（`OPEN_FOLLOWING_AFTER_SWITCH`。v1.4.0）。
   ただし**個別ポスト（`/ユーザー/status/数字`）を開いたまま切り替えたときは、そのポストへ戻る**
   （`RETURN_TO_POST_AFTER_SWITCH`。v1.11.0）。別のアカウントで返信・いいねし直せる。
   X は切替後にページを読み込み直すので、戻り先は切替を押した印（`sessionStorage` のキー
   `tm-x-switch-after`）に入れておき、読み込み直した後に開き直す。画像を開いた `/photo/1` 等の
   続きは付けず、ポスト本体を開く。ポスト以外のページからの切替は、元のページへは戻らない
   **投稿画面（`/compose/post`）で押したとき**は、書きかけの文を取っておき、ホームを開き直して切り替え、
   終わったら投稿画面を開いて文を入れ直す（v1.13.0）。投稿画面には左上のアイコンも下のタブも無く、
   X の切替メニューを開けないため。戻せるのは文だけで、画像・返信先・引用は戻せない。
   入れ直せなかったときは、トーストの「文をコピー」で文をコピーできる。
   取っておいた文は `sessionStorage` のキー `tm-x-switch-draft` に入れ、10分で捨てる
5. アイコンの下の区切り線から下が操作のボタン。記号ではなく文字で出す。ふだんは「しまう」だけで、
   現在のアカウントのアイコンを押すと、その上に「更新」「大きく」「小さく」「自由／6か所」が出る（v1.10.0・v1.12.0）。
   もう一度押すか、ドックの外を触ると引っ込む。
   「更新」は、関係ないアカウントが入ったときなどに押すと、X の切替メニューを開いて一覧を読み直し、
   実際にログインしているアカウントだけに置き換える（v1.5.0 で「読込」として足し、v1.5.1 で「更新」に
   名前を変えた）。現在のアカウントが分からないページでは押す先が無いので、「更新」を常に出す
6. 置き場所を変えるときは、ドックを引っぱって離す
   （アイコンやボタンの上から引っぱってもよい。少し指がぶれただけなら普通のタップになる）。
   置き方は2通りあり、現在のアカウントのアイコンを押すと出るボタンで切り替える（v1.12.0）。
   ボタンの文字は「押すとなる置き方」で、切り替えるとトーストで知らせる
   - **6か所**（既定）: 左右それぞれの上・中・下。画面を縦に3つに分け、離した段と左右で決める
     （v1.11.0 までは四隅だけだった）
   - **自由**: 左右どちらかの端に付けたまま、離した高さにそのまま置く。高さは画面の高さに対する割合で
     覚える（`localStorage` のキー `tm-x-switch-free-spot`）ので、画面の向きが変わっても大きく外れない。
     iPhone の下のタブや投稿ボタンには重ねない（下の隅と同じ高さより下へは行かない）

   置き方は `localStorage` のキー `tm-x-switch-place-mode`（`snap` / `free`）に覚える。
   切り替えたときは、いまドックがある所から移る先を決めるので、切り替えただけでは大きく動かない
7. 「しまう」を押すと、ドックは画面端のつまみ（‹ / ›）だけになる。つまみを押すと戻る。
   つまみは v1.12.0 で 24×56px から 34×88px に広げ、矢印も文字ではなく太い線の図形にした
   （小さくて見つけにくく、矢印も細かったため）。広げすぎて邪魔だったので、v1.12.1 で 26×68px にした。
   つまみはスクロールで濃さを変えず、いつも薄いまま（不透明度 0.5、設定の `TAB_OPACITY`）にしている（v1.12.2）。大きさは設定の `TAB_WIDTH_PX` などで変えられる。
   しまった状態は端末に覚える（`localStorage` のキー `tm-x-switch-tucked`）ので、
   再読み込みしても別のタブでも続く
8. 大きさは「大きく」「小さく」で、アイコン 32 / 36 / 40 / 44 / 48px の5段階から選ぶ（v1.10.0）。
   押すたびにその場で変わり、端末に覚える（`localStorage` のキー `tm-x-switch-size`）。既定は 44px。
   X の本文は画面の左端から 65px 前後で始まるので、iPhone で左に置いて本文にかけたくなければ
   36px 以下にする（ドックの右端が 58px 以下になる）。段階は設定の `DOCK_SIZES` で変えられる。
   v1.9.0 では iPhone 幅だけ 36px に固定していたが、元の大きさの方がよいこともあるため選べるようにした

v1.7.0 で「移動」ボタンと四隅の表（↖ ↗ ↙ ↘）を外した。ドックを引っぱれば同じことができ、
ボタンが1つ減るぶんドックが短くなるため。

v1.3.0 で「⋮」とメニューをやめ、操作は区切り線の下の文字のボタン（「移動」「しまう」）にした。
「⋮」や矢印の記号だけでは何のボタンか分かりにくく、ドックの「しまう」の矢印が、つまみの
「出す」矢印と紛らわしかったため。矢印はつまみ（出す）だけに使う。

v1.2.0 で「しまう」をメニューの中からドックの常設ボタンへ移し、メニューの
「アカウントを読み込む」「一覧を消去」を外した。アカウントが増えた・減ったときは、X の切替メニューを
一度開けば覚え直す（「既存のアカウントを追加」が見える一覧を読むと、保存済みを置き換える）。
一覧が空のときの「読込」ボタンは残している。コンソールでは `__tmXSwitch.load()` / `__tmXSwitch.forget()` で
同じことができる。

v1.0 の「最小化」（現在のアカウントのアイコンだけ残す）と「このタブでは隠す」は、
v1.1.0 で廃止して「しまう」にまとめた。最小化しても邪魔さがほとんど減らず、
その状態では切り替えもできなかった。隠すほうは、戻す手段が画面に無く、
タブを閉じるまで戻せなかった。v1.0 で「隠す」を選んだタブも、更新後は表示される

## 元版（TapShift）から直したこと

| 元版の問題 | 直し方 |
|---|---|
| ページ全体の `UserCell` と `[role=menuitem]` から一覧を拾っていた。フォロワー一覧やおすすめユーザー、ポストの「…」メニュー（「@xxxさんをフォロー」）の相手まで自分のアカウントとして登録された | 「既存のアカウントを追加」「ログアウト」等の目印と同じ入れ物にある、**アバターと @ハンドルを持つ押せる要素**だけを覚える |
| 切替先をページ全体から探していた。タイムラインに同名ユーザーが出ていると、それを押してプロフィールへ飛ぶ | X の重なり層（`#layers`。メニュー・ドロワー・シートが描かれる場所）の中だけを探す。プロフィールへのリンク（`/ハンドル`）は押さない |
| `innerHTML` を使っていた | `createElement` と `textContent`、SVG は `createElementNS` |
| 切替後に再読み込みが起きないと、ボタンが押せないまま固まった | 一定時間（`RELOAD_TIMEOUT_MS`）で成否を確かめてボタンを戻す |
| 初回に勝手にドロワーを開いていた | 読み込みは「読込」ボタンかメニューから手動で行う |
| ログアウトしたアカウントが一覧に残り続けた | 「既存のアカウントを追加」がある一覧（全件が出ている）を読んだら、保存済みを置き換える |
| モバイル幅で現在のアカウントを取れなかった（下のタブにプロフィールが無い） | 左上のアイコンの画像・表示名を、覚えている一覧と突き合わせる（v1.0.1） |

## 作りの要点

- ハンドルは、アバターの入れ物の testid → `aria-label` → 表示テキストの順に探す。
  ドロワーの「他のアカウント」はアバターだけで文字を持たないことがあるため
- 開く経路は、デスクトップ幅の左下のアカウントボタン → 無ければ左上のアイコン
  （ドロワー）→ ドロワーに切替先が無ければ「アカウント」ボタン（`aria-label` に
  「アカウント」を含む／`/account/switch` へのリンク）で一覧を開く
- 一覧が重なり層ではなく独立したページ（`/account/switch`）として開く場合も、
  そのページの本文を探す。読み込みの後は `history.back()` で戻る
- ドックは Shadow DOM の中に置く。X の CSS の影響を受けず、X 側の
  `MutationObserver` にも自作要素の変化が上がらない
- 一覧は `localStorage`（キー `tm-x-switch-accounts`）。`storage` イベントを見ているので、
  別タブで覚えた分も反映される

## iPhone の実機診断で分かったこと（v1.0.1）

v1.0.0 は iPhone で「読込」が失敗した。診断で次の2点が分かった。

- **モバイル幅では `#layers` にメニュー以外も常に居る。** 上のバー（`TopNavBar`）・
  下のタブ（`BottomBar`）・投稿ボタン・タブの `grid`・新着ピルがすべて `#layers` の中にある。
  v1.0.0 はこれをメニューと区別しておらず、診断の構造記録が上下のバーで上書きされ、
  ドロワーの中身が残らなかった
- **左上のアイコン（`DashButton_ProfileIcon_Link`）はハンドルを持たない。**
  アバターの testid は `UserAvatar-Container-unknown`、`aria-label` は
  「プロフィールメニュー 表示名」。v1.0.0 は現在のアカウントを「@unknown」と誤認していた

v1.0.1 で直したこと:

- 上下のバー等（`PERSISTENT_SELECTORS`）は、切替先や「アカウント」ボタンを探す範囲から外す。
  メニュー・ドロワーは `#layers` の中の `dialog` / `menu` / `aria-modal` として扱う
- testid の `unknown` はハンドルと見なさない。現在のアカウントは、左上のアイコンの
  画像（大きさの違いを除いた URL）→ 表示名の順に、覚えている一覧と突き合わせる。
  ドロワーを開いたときは、中の自分のプロフィール（`/ハンドル` へのリンクで @ハンドルを表示）
  から自分を覚える
- ドロワーに「アカウント」ボタンが無くても、他のアカウントのアイコンが見えていれば、
  その分だけ覚える（足すだけ）

## 個別ポスト等での切替（v1.0.2）

v1.0.1 で「ホームでは動くが、個別ポストでは動かない」と報告があった。個別ポスト等では
左上がアイコンではなく「戻る」になり、ドロワーを開けないため。

- 左上のアイコンが無いときは、下のタブの「ホーム」（`AppTabBar_Home_Link`）を押して
  いったんホームへ移り、そこでドロワーを開く
- 終わったら（失敗・読み込みのとき）元のページへ戻る。切替に成功したときは戻らず、
  ホームの「フォロー中」を開く（v1.4.0）。履歴で戻り、
  `RETURN_CHECK_MS`（既定0.6秒）後に元のページに着いていなければ開き直す。
  X が途中のページを置き換える（`/account/switch` → `/home` 等）と、履歴の段数どおりに
  戻っても着かないため
- X が切替後にページを読み込み直した場合は、起動時にホームの「フォロー中」を開く（v1.4.0。
  v1.3.0 までは元のページへ戻していた）
- 左上のアイコンが無いページでは現在のアカウントを取れないので、同じタブで最後に
  確かめた値（`sessionStorage` のキー `tm-x-switch-current`）を使う。切替先を押した時点で
  切替先に書き換える。この値は古いことがあるため、「現在のアカウントなので何もしない」
  判定には使わない
- 左上のアイコンを構造で探すときは、上のバー（`TopNavBar` / `header`）の中に限る。
  プロフィールページの大きなアイコン等を拾わないため

## 自動で開けなかったとき（v1.1.1）

v1.1.0 で「読込」が「アカウント一覧を開けませんでした」で失敗し、X の切替メニューを手で開けば
覚える、と報告があった。自動で開く途中のどこで止まったかは、まだ分かっていない。

- 失敗しても、途中まで開いたドロワー等は閉じずに残す。続き（「アカウント」ボタン等）を手で押せば、
  開いた一覧をその場で覚え、「N件のアカウントを覚えました」と知らせる
- 失敗の案内に止まった段階を出す（「左上のアイコンが見つからない」「ドロワーが開かない」
  「ドロワーの中に「アカウント」ボタンが見つからない」「アカウント一覧が出ない」）
- 失敗の案内に「記録をコピー」ボタンを付けた。1タップで診断の記録をクリップボードへ写せる
- X は部品を初めて開くときに読み込むので、メニュー・ドロワーを待つ上限（`MENU_WAIT_MS`）を
  3秒から5秒に延ばした

## iPhone の一覧ページで読み込めない問題（v1.1.2）

v1.1.1 の「記録をコピー」で取れた実機の記録で原因が分かった。iPhone では、ドロワーの
「すべてのアカウントを表示」（`a[data-testid="switcher"][href="/account/switch"]`）から
独立したページ `/account/switch` が開き、その中は次のようになっている。

- 現在のアカウント: `li[role="listitem"][data-testid="AccountSwitcher_Switch_Button"]`（押せない）
- 他のアカウント: `button[data-testid="AccountSwitcher_Switch_Button"][aria-label="@ハンドルに切り替える"]`
- `AccountSwitcher_Add_Button`（既存のアカウントを追加）、「すべてのアカウントからログアウト」

v1.1.1 までは `AccountSwitcher_` で始まる testid をすべて「目印」と見なし、
アカウントの候補から外していた。そのため一覧のページは開けても候補が0件になり、
「アカウント一覧が出ない」で失敗していた。v1.1.2 では `AccountSwitcher_Switch_Button` を
アカウントの項目として扱い、押せない `li` も候補に含める。

## パソコン・iPad で一番下のアイコンが頭文字になる問題（v1.1.3）

パソコンと iPad で、ドックの一番下のアカウントがアイコンではなく ID の頭文字で表示されると報告があった。

切替メニューの中では、現在のアカウントは押せない項目になっている。押せる要素だけを候補に
集めているので拾えず、「現在のアカウント」として末尾に足していた。その際アイコンを空、
表示名を ID にしていたため、一番下（＝後から足した現在のアカウント）が ID の頭文字になった。

- 現在のアカウントを足すときは、切替メニューの中のそのハンドルのアバター（押せない項目でもよい）
  から、アイコンと表示名を取る。無ければ左下の切替ボタン（`SideNav_AccountSwitcher_Button`）から取る
- v1.1.2 までに壊れた状態で覚えた分は、読み込み直さなくても、ページを開いたときに
  切替ボタン等から直す

## 切替後はホームの「フォロー中」へ（v1.4.0）

切替後は元のページへ戻さず、ホームの「フォロー中」タブを開くようにした（要望）。

- 切替を押した時点で `sessionStorage` に印（キー `tm-x-switch-after`）を残す。X が切替後に
  ページを読み込み直したら、起動時にこの印を見て「フォロー中」を開く（1分以上前の印は捨てる）
- ホーム以外に居たら、下のタブ等の「ホーム」（`AppTabBar_Home_Link`）で移る。無ければ `/home` を開き直す
- 「フォロー中」タブ（`[role="tablist"] [role="tab"]` の「フォロー中」/`Following`）が出るのを
  最大6秒待ち、選ばれていなければ押す。探し方は `x-following-tab.user.js` と同じ
- 読み込み直さずに切り替わった場合も同じ。失敗したときは従来どおり元のページへ戻る

あわせて、パソコンでアイコンの画像の上からマウスで引っぱるとブラウザ標準のドラッグ（画像や、
ドックの下にあるページのリンク）が始まり、ドックを動かせなかった不具合を直した。マウスで押した
時点で標準のドラッグ・文字選択を始めさせない（クリックは止まらない）。

## パソコンで一覧に関係ないアカウントが増える問題（v1.4.1）

パソコンで、ドックのアイコンがどんどん縦に伸びる（関係ないアカウントを覚える）と報告があった。

「ドロワーを開いたら、中の自分のプロフィール（`/ハンドル` へのリンクで @ハンドルを表示）から
自分を覚える」処理（v1.0.1）が、iPhone のドロワーに限らず、重なり層に開いた画面すべてで
働いていた。パソコンで画像を拡大する・返信する・いいね一覧を開くと、中の投稿者やユーザーが
「自分」として覚えられ、開くたびに一覧が伸びていた。

- この処理は、左上のアイコンからドロワーを開く画面幅（モバイル）でだけ使う。
  デスクトップ幅（左下の切替ボタンがある）では使わない
- ポスト（`article`）を含む重なり層は対象外
- 左上のアイコン（自分）と画像が違うアカウントは自分と見なさない
- あわせて、切替メニューの文言の目印（「ログアウト」等）は40文字以内の要素に限る。
  長い文章に含まれているだけの入れ物を切替メニューと取り違えないための予防

すでに増えてしまった分は、ドックの「更新」（v1.5.0。当初の名前は「読込」）を押すか、X の切替メニュー（パソコンでは
左下のアカウントボタン）を一度開くと、「既存のアカウントを追加」がある一覧で置き換わって消える。

v1.5.0 で、ドックの区切り線の下に「読込」を足し、v1.5.1 で「更新」に名前を変えた（要望）。一覧を先に消すのではなく、切替メニューの
一覧すべてを読めたときだけ置き換えるので、途中で失敗しても今の一覧は残る。そのため確認は出さない。
一覧が空のときはアイコン欄の大きな「読込」（初回の読み込み）だけを出し、下の「更新」は隠す。

## iPhone で下の隅に置くとき（v1.6.0）

iPhone の Safari で左下・右下に置くと、ドックが X の左下のアイコンや右下の投稿ボタンに
重なって隠していた。ドックの下端が「画面の下端から 62px」固定で、下のタブのすぐ上にあったため。

- 下のタブ（`BottomBar`）がある画面では、ドックと同じ側（画面の端から `SIDE_BAND_PX`＝96px の中）で
  下のタブより上に浮いている X の要素（押せる要素・アバター・投稿ボタン）を実際に測り、
  その上端から `BOTTOM_GAP_PX`（12px）上にドックの下端を置く
- 何も測れなくても、下のタブの上端から投稿ボタン1つ分（`MOBILE_MIN_LIFT_PX`＝72px）＋12px は上げる
- 「浮いている」とみなすのは、X の重なり層（`#layers`）の中か `position: fixed` の中にあるものだけ。
  タイムラインのポストが画面の下に来ても位置は変わらない。開いているドロワー等の中身、
  通知（`role=alert` / `status`）も測らない
- 上げる上限は画面の高さの半分（`MAX_BOTTOM_RATIO`）
- しまったときのつまみも同じ高さに付く
- 下のタブが無い画面（デスクトップ・iPad）と、上の隅に置いたときは従来の位置のまま
- 診断（`#tmswitch` / `__tmXSwitch.dump()`）の「■ 下の隅の高さ」に、左下・右下の高さと、
  決め手になった要素が出る。位置が合わないときはこれを送ってもらえば直せる

## iPhone で下の隅の位置がときどき下がる問題（v1.7.1）

v1.6.0 の後、「基本的には良いが、ときどき下にずれる」と報告があった。下のタブを見つけられなかった瞬間
（X が描き直した・ドロワーを開いた・ページを開いた直後で下のタブがまだ無い等）に「測れない」として、
旧来の既定の位置（下から 62px）へ戻していたため。模擬DOMでも、下のタブが消えると 137px → 62px に落ちるのを確認した。

- 幅 `MOBILE_MAX_WIDTH`（599px）以下の画面では、下の隅の高さを必ず
  `MOBILE_BOTTOM_MIN_PX`〜`MOBILE_BOTTOM_MAX_PX`（132〜240px。どちらもセーフエリアの分を足す）に収める。
  CSS の `clamp()` で決めているので、測り損ねても測った値がおかしくても、この範囲の外には出ない
- 測れなかったときは、最後に測れた高さ（`localStorage` のキー `tm-x-switch-lift`）を使う。
  次にページを開いたときも、下のタブが出る前からその高さに置く。一度も測れていなければ下限（132px）
- 診断の「■ 下の隅の高さ」に、範囲・最後に測れた値・いまのドックの下端を足した
- デスクトップ・iPad（幅 600px 以上）は従来どおり

## 未確認の点

iPhone のドロワーの中身の DOM は、全体をまだ確認していない。一覧のページ
（`/account/switch`）の構造は v1.1.1 の診断で確認済み。

## 診断（iPhone 可）

URL の末尾に `#tmswitch` を付けて開く（例: `https://x.com/home#tmswitch`）。
画面下に診断パネルが出るので、「読込を試す」を押し、終わってから「コピー」を押す。
左上のアイコンを隠さないよう、パネルは画面下に置いている。
コンソールが使える環境なら `__tmXSwitch.dump()` でも同じものが出る。

切替の記録と構造の記録は `sessionStorage` に保存しているので、再読み込みしても
タブを閉じるまで残る。失敗した後で `#tmswitch` を開いても、その時の記録が見える。

- **■ 現在のアカウント**: 取れたハンドルと取得元
- **■ 開くボタン**: メニュー・ドロワー・アカウント一覧の各ボタンが見つかったか
- **■ 切替メニューと判定した入れ物**: 目印と、中にあった候補（ハンドル・取得元・要素）
- **■ 直近の切替の記録**: どの段階まで進んで、どこで止まったか
- **■ いま開いているメニュー・ドロワー**: `#layers` の中の `dialog` / `menu` / `aria-modal`
- **■ 最後に開いていたメニュー・ドロワーの構造**: 骨格（role / testid / aria-label /
  href / 押せる要素の中の文字 / アバター画像のファイル名）。上下のバー等は省く。
  閉じた後でもコピーできる
