# ページ本文コピー について（ファイル: `page-to-markdown.user.js`）

表示中のページの本文を **Markdown にしてクリップボードへコピー**する。
**v1.2.0から、設定済みならGoogle Driveの「参考記事アーカイブ」へも保存する。**
初回設定は [Drive保存の設定手順](../page-markdown-drive-setup.md) を参照。
受け口は `page-markdown-receiver.gs`。URLとトークンはTampermonkey内だけに登録する。
**v1.3.0から、届かなかった保存を控えておき、あとで送り直す**（下の「Drive保存が届かなかったとき」）。
**v1.6.0から、本文の画像（図表など）もDriveに保存する**（下の「本文の画像」）。
**v1.7.0から、成人向けのサイトではDriveに保存しない**（下の「成人向けのサイトの除外」）。
**v1.7.1で、ページ単位の判定がSPAで残り続ける不具合と、タイトルの語の当てすぎを直した**（下の「v1.7.1 の修正」）。
**v1.8.0から、成人向けと判定したページでもボタンを消さない。**
**v1.9.0から、成人向けのページは画像を除いた文章だけ Drive に保存する。未成年を示す語があればコピーだけにする**（下の「成人向けのサイトの除外」）。
**v1.10.0から、X はポストのページだけ Drive に保存する。指定したページではボタンを隠せる**（下の「X のポスト」「ボタンを隠すページ」）。
**v1.11.0から、X のポストが並ぶだけのページ（タイムライン・リプライ・リポストの一覧・リストなど）ではボタンを隠す。**
参考になるサイトを AI に共有したいとき、URL では読めないことがあるため、
ブラウザで見えている文章をそのまま貼れるようにするためのもの。

## 使い方

- 📋 ボタン、または **Alt+Shift+C** でコピーする。
  コピー後に「○○文字をコピーしました」とトーストが出る（6万文字を超えると注意が付く）
- **ボタンは指（マウス）でドラッグして、画面のどこへでも動かせる**。動かしたあとの位置は
  そのサイトで覚えている。初期位置は、画面の上のほうで中央よりやや右
  （中央上はタイトル、右上はメニューボタンと重なりやすいため）。
  動かさずに押せば（タップ）コピーになる
- **文字を選択していれば、その範囲だけ**をコピーする。このとき周辺メニューの除外はせず、
  選んだものをそのまま渡す。ボタンを押しても選択は解除されない
- 選択していなければ、**本文を自動判定**してコピーする
- 出力の先頭に、タイトル・URL・取得日時が付く

## X のポスト（v1.4.0）

X（x.com / twitter.com）のポストページでは、専用の整え方でコピーする。
文字を選択しているときは、これまでどおり選択範囲を優先する。

- **URL の status ID と一致するポストだけ**を取る（以前は文字数が最大の `article` を選んだため、
  元ポストの代わりに返信の本文が保存されることがあった）。
  前後のポスト・返信もまとめて取りたいときは、設定の `INCLUDE_X_REPLIES` を `true` にする
- 先頭は `# 名前 (@ID) のポスト` と、URL・投稿日時（JST）・取得日時。
  X の `<title>` は投稿全文を含むので、見出しにしない（本文との二重と、大きな太字を避ける）
- Drive のファイル名も、`名前 (@ID) 本文の冒頭40字` になる
- 本文の見出しは1段下げる（長文記事の `#` が文書の見出しと同じ大きさにならない）
- 投稿者名・@ID・時刻・「·」・数字だけの行は本文から外し、反応数は末尾の
  `反応: 表示 1.3万 / 引用 2 / リポスト 31` の1行にまとめる（`INCLUDE_X_STATS` で外せる）
- 絵文字は文字のまま、意味のない画像 alt は `[画像]`、表示文字がURLのリンクは表示のほうだけにする
- ポストを狙う手がかりは構造（`<time datetime>` を持つ `article`、`/status/<ID>` へのリンク）。
  `data-testid` には頼らない。外れたら `window.__tmCopyText.dump()` で選んだポストを確認できる
- status ID が URL に無い・一致するポストが見つからないページは、通常の本文判定に戻る
- **v1.10.0から、Drive に保存するのはポストのページだけ**。ポストのページは
  `/<ユーザー>/status/<ID>`（写真・動画を開いた `/photo/1` `/video/1` を含む）。SPA でポストを開けば、その場で保存できるようになる
- **v1.11.0から、ポストが並ぶだけのページではボタンを隠す**。タイムライン（`/home`）・プロフィール・リプライ（`/with_replies`）・
  リスト・検索・通知、それに `/status/<ID>/retweets` `/quotes` `/likes`（リポスト・引用・いいねの一覧）。
  Drive には保存しない。Alt+Shift+C のコピーは使える（トーストに「X はポストのページだけ Drive に保存します」）。
  ボタンを灰にして残したいときは、設定の `HIDE_ON_X_LISTS` を `false` にする
  （v1.10.0 は `/retweets` などもポストのページとして保存していた）
- Drive のファイル名にする本文の冒頭は、画像（アイコンなど）だけの行を飛ばした最初の行にする（v1.10.0）

## ボタンを隠すページ（v1.10.0）

ボタンが邪魔なページでは、ボタンを隠せる。

- Tampermonkey のメニュー「**このページでボタンを隠す**」で、URL を入力する（今のページの URL が入っている）。
  `*` は任意の文字列。例: `https://example.com/admin/*` でその下のページすべて、`https://example.com/*` でサイト全体
- 照らし合わせるのは `#` より前の URL（クエリ `?…` は含む）。大文字小文字は区別しない
- 隠したページでも **Alt+Shift+C は使える**。トーストも出る。ボタンのあった場所は、下のページをそのまま押せる
- SPA で当たらないページに移ればボタンが戻る
- 外すときはメニュー「**ボタンを隠したページを一覧・解除**」で番号を選ぶ
- 一覧は Tampermonkey の保存領域（キー `tm-copy-text-hidden-pages`）に入る。スクリプトを更新しても消えない
- X のポストが並ぶだけのページは、一覧に入れなくても隠す（上の「X のポスト」）。この一覧には出ない

## 本文の画像（v1.6.0）

note の図表のような、本文に入っている画像を記事と一緒に残す。

- 本文の画像は「`![画像1: alt](元のURL)`」の形で書く（クリップボードにも同じ形で入る）。
  同じ画像の2回目は同じ番号
- 保存の対象は本文の中の画像だけ。表示の幅か高さが120px未満のもの（アイコンなど）は保存せず、
  今までどおり alt だけを「[画像: alt]」で残す。1記事20枚まで（`IMAGE_MAX`）
- 後から読み込む作りのサイトに合わせ、`srcset`（いちばん大きいもの）・`data-src` などから本当のURLを拾う
- 画像を包むリンクの先が画像なら、そちらを使う（note など。読み込み前でまだ表示されていない画像も拾える。v1.6.1）
- 小さい画像かどうかは、確かな大きさ（表示の大きさ・読み込み済みの実寸・width/height 属性）だけで判断する。読み込み前の仮の画像（1px など）は小さいとみなさない。リンクの先が画像なら大きさは問わない（v1.6.2）
- 受け口は `image/jpg` などの正式でない種類名も受け付ける。種類名が汎用（`application/octet-stream`）のときは、URLの拡張子で判断する（v1.6.1）
- 画像を取りに行くのは受け口（GAS）。Tampermonkey の通信先は増えない。
  ログインしないと見えない画像（有料記事など）は保存できない
- 保存先は「参考記事アーカイブ」の中の「`<記事のファイル名>_画像`」フォルダ。ファイル名は `01_alt.png` の形
- 記事の `.md` の末尾に「## 画像（Driveに保存）」の一覧が付く。本文の「画像N」と番号で対応し、
  保存できなかった画像は理由と元のURLが残る
- 保存できたかはトーストに出る（「…（画像2枚、保存できなかった画像1枚）」）
- 送り直しでは画像を取り直さない（一覧が付いていれば、同じ送信として扱う）
- X（旧Twitter）の画像は Drive に送らない。成人向けかどうかを見分けられないため（v1.7.0）

## 成人向けのサイトの除外（v1.7.0）

成人向けのサイトの画像が Drive に入らないようにする。スクリプトと受け口（GAS）の両方で判定し、
どちらかが成人向けと判定すれば画像は保存しない。

v1.9.0 から、Drive に送るものを3段階に分ける。Google のアカウント停止のきっかけは、報道で見る限りほぼ画像なので、
成人向けのページでも文章は残す。ただし未成年を示す語がある文章は、画像と同じ方針の対象になりうるので送らない。

| 段階 | ボタンの色 | 条件 | Drive に送るもの |
|---|---|---|---|
| 画像も保存 | ふつう（濃い灰） | 成人向けの判定に当たらない | 本文と画像 |
| 文章だけ保存 | 黄 | 成人向けと判定したサイト・ページ | 本文だけ。画像の一覧は送らず、本文の「`![画像1: alt](URL)`」は「`[画像1: alt]`」にする |
| コピーだけ | 橙 | 成人向けと判定し、さらにタイトル・本文に未成年を示す語がある | 送らない |

- 未成年を示す語は `MINOR_WORDS`（児童・少女・ロリ・小学生・中学生・女子高生・JK・17歳以下の年齢など）。
  スクリプトと受け口の両方で見る。成人向けと判定したページでだけ見るので、ふつうの記事の「小学生」では変わらない。
  「美少女」も当たるので、成人向けのサイトでは多くのページがコピーだけになる。外れてもコピーはできる
- 「18歳未満の方は閲覧できません」のような注意書きでは当たらない（18歳以上の年齢と「未成年」は語に入れていない）
- クリップボードには、どの段階でも本文をそのまま入れる（画像の URL も残る）
- 「参考記事アーカイブ」フォルダは共有しないこと。共有すると、文章だけの保存も公開とみなされうる

判定のしかた:

| 判定のしかた | どこで | 除外する範囲 |
|---|---|---|
| ドメインの末尾（`.xxx` `.adult` `.porn` `.sex`）と語（porn・hentai・xvideos・fanza など） | スクリプト・受け口 | サイト全体 |
| Cloudflare の家族向け DNS（`family.cloudflare-dns.com`、1.1.1.3 と同じ判定）が 0.0.0.0 を返す | スクリプト・受け口 | サイト全体 |
| 年齢区分の meta（`rating` が adult・RTA など）、タイトルの「R-18」「18禁」「成人向け」「アダルト」など | スクリプト | そのページだけ（SPA で別の記事に移れば判定し直す） |

- 成人向けと判定したサイト・ページでは、ボタンを黄（または橙）にする。トーストは
  「Driveに文章だけ保存し、コピーしました（成人向けと判定したので、画像は送っていません）」または
  「○○文字をコピーしました（本文）。成人向けで未成年を示す語があるので、Driveには送っていません（理由）」
  （v1.7.0〜1.7.1 はボタンを消し、コピーもしなかった。v1.8.0 はコピーだけだった）
- 初めて開いたサイトは、家族向け DNS に一度だけ問い合わせる（結果は7日間使い回す）。成人向けならボタンの色を変える。
  問い合わせで送るのはホスト名だけ（ページの URL や本文は送らない）
- サイト単位の判定は、除外の一覧（Tampermonkey の保存領域）に自動で足す。
  メニュー「このサイトを除外」で手でも足せる。「除外したサイトを一覧・解除」で番号を選んで外せる。
  外しても、家族向け DNS と受け口の判定はそのまま働く（外せるのは、ドメイン名の語による判定と手動の除外だけ）
- 押したときにもう一度確かめる。送る直前に家族向け DNS が成人向けと答えたら、画像を外して文章だけ送る。そのあとはボタンが黄になる
- 文章だけの送信には `textOnly: true` を付ける。受け口はこのとき家族向け DNS に問い合わせず、
  未成年を示す語が無ければ本文を保存する（画像の一覧が付いていたら「不正」として断る）
- 受け口は、`textOnly` の無い送信で、記事のサイトが成人向け、または判定できない（家族向け DNS に届かない）ときは保存しない。
  判定できないときは「サイトの判定に失敗しました」と返し、スクリプトはあとで送り直す
- 受け口に「未成年を示す語」で断られたら、控えを消す。サイトは除外の一覧に足さない（そのページの中身の問題のため）
- 受け口は、画像の配信元も1つずつ判定する。成人向け・判定できない配信元の画像は取りに行かない。
  画像の転送（リダイレクト）は自動でたどらず、転送先のサイトも判定してから取りに行く（3回まで）
- 除外したサイトの控え（未保存）は、画像を外して文章だけ送り直す。未成年を示す語があれば送らずに消す
- 受け口を更新したら、`setup` を実行すると、判定が働くかがログに出る
  （`nudity.testcategory.com` が「成人向け」、`example.com` が「問題なし」なら正常）

### v1.7.1 の修正

v1.7.0 には、成人向けでないページでもボタンが消える不具合が2つあった。

- **SPA で消えたままになる**: note・X などは記事を移っても読み込み直さない。v1.7.0 はページ単位の判定
  （タイトルの語・年齢区分の meta）を開いたときの1回しかせず、しかもサイト単位の除外と同じ旗で持っていた。
  そのため、該当するページを一度開く（または押して断られる）と、同じタブで別の記事に移ってもボタンが戻らなかった。
  v1.7.1 からは、タイトルや URL が変わるたびにページ単位の判定をやり直す。サイト単位の除外とは別に持つ
- **タイトルの語の当てすぎ**: 「エロ」「アダルト」を部分一致で見ていたため、「ヒエログリフ」「エロージョン」
  「アダルトチルドレン」「アダルトラーニング」のような記事でも消えていた。カタカナ語の一部のときは当てない。
  「R-18」も英数字の続き（「PR-180」など）では当てない

ボタンが黄・橙になった理由や、ボタンが見当たらないときは、Tampermonkey のメニュー「**ボタンの色・保存の判定を確認**」を開く（v1.8.0）。

- サイトを除外しているときは、その理由と、解除するメニューの名前が出る
- ページ単位の判定のときは、理由とタイトルが出る
- 判定していないときは、ボタンを初期位置に戻せる（画面の外や、ほかの表示の陰にある場合）

限界: 一般のサイト（ニュース、SNS、画像投稿サイトなど）に混ざる成人向けの画像は、ドメインでは見分けられない。
X の画像は送らないようにしたが、ほかの投稿サイトの画像は、タイトルや meta で分からなければ保存されうる。
家族向け DNS の分類は Cloudflare のもので、誤判定（成人向けでないサイトの除外）もありうる。

## Drive保存が届かなかったとき（v1.3.0）

ボタンを押したらすぐ次の操作に移れるようにするための仕組み。

- 送る前に、本文・タイトル・URLの**控え**をTampermonkeyの保存領域に取る
  （キー `tm-copy-text-pending:<送信ID>`。1件ずつ別キーなので複数タブで書いても消し合わない）。
  届いたと確認できたら消す
- コピーの結果はDriveの応答を待たずに出す（「コピーしました。Driveへ送信中…（移動して大丈夫です）」）
- 控えが残っていると、📋 ボタンの右上に**赤い件数**が出る
- 自動の送り直し:
  - 次にどこかのページを開いたとき（最後に試してから15秒・1分・5分・30分と間を空ける。
    移動直後は元の送信がまだ届く途中かもしれないため）
  - 次にDrive保存が成功したとき（つながっているうちに、残りもまとめて送る）
  - アプリ・タブに戻ったとき、電波が戻ったとき
- 手動: Tampermonkeyのメニュー「**未保存を一覧・再送**」。タイトル・URL・失敗理由の一覧を確認して送る。
  要らない控えは「**未保存の控えを削除**」
- 送り直しは元と**同じ送信ID・取得日時**で送る。GAS はそこからファイル名を決め、同名・同内容なら
  既存のファイルを返すので、実は届いていた分を送り直しても二重にならない
- 控えは最大20件。超えた分は控えず、コピーだけ残る。50万文字を超える本文は控えない
- 診断: `window.__tmCopyText.pending()` で控えの一覧（文字数・試行回数・理由）が表で出る

送信が Google に届いたあとは、ページを離れても GAS が最後まで動いて保存する。
控えが要るのは、届く前にページを離れた・アプリを閉じた・電波が切れたときのため。

### 受け口に断られたとき（v1.5.0）

v1.4.0 までは、受け口（GAS）が内容を見て断った場合も通信の失敗と同じに扱い、
送り直しを延々とくり返していた。控えが消えず、件数の「1」が残り続けることがあった。

- 断られた理由は、受け口の文言をそのまま出す（「Drive保存を確認できません…」に置き換えない）
- 「送信IDが重複しています」（同じIDで別の中身が保存済み）: 新しい送信IDを付けて送り直す。
  中身は失わず、Drive には別のファイルとして保存される
- 「…が不正です」（中身を受け付けない）: 自動では送り直さない。理由と消し方を一度だけ出す。
  メニュー「未保存を一覧・再送」の一覧に「（自動では送り直しません）」と出る。手動の送り直しでは送ってみる
- 混雑・トークン違いなどは、今までどおり待って送り直す
- 途中で切れた絵文字（対になっていないサロゲート）は、送る前に `U+FFFD` に置き換える。
  そのまま送ると Drive に書いた時点で別の文字になり、送り直したときに「中身が違う」と断られていた

## 何が入り、何が入らないか

| 対象 | 扱い |
|---|---|
| 本文（見出し・段落・リスト・コード・表・引用・リンクURL・画像のalt） | Markdown にして含める |
| 画面外（スクロールしないと見えない部分） | **含める** |
| 閉じた折りたたみ（`details`・タブ・`aria-controls` で開閉される領域・CSS で畳まれた領域） | **開いた状態として含める** |
| メニュー・サイドバー・フッター・サイトの header・広告・共有ボタン・関連記事・リンクだらけのブロック | 含めない |
| 広告ブロッカーが `display:none` にした要素、折りたたみと関係のない非表示要素 | 含めない |
| 折りたたみの中の広告らしいもの | 含めない |

折りたたみの中身と広告ブロッカーの非表示は、どちらも `display:none` で隠れるため、
隠れているかどうかだけでは区別できない。そこで「隠れている要素は、折りたたみの仕組み
（`details`・`role=tabpanel`・`aria-controls`・直前が `aria-expanded` のボタン・
`accordion` などの class）が確認できたものだけ含める」というルールにしてある。

## 作りの要点

- 本文コンテナは、`[itemprop="articleBody"]` → `.entry-content` → `article` → `main` …
  の順に試し、それでも見つからなければ**文字量スコア**（段落の文字量を親・祖父へ加点）で選ぶ
- 除外は**構造で判定**する（タグ・role・リンク密度）。class の判定は補助
- 表は**データ表だけ** Markdown の表にする。入れ子・1列・1行・中にリストや見出しが
  ある表はレイアウト用とみなし、普通の段落として流す
- 判定は**コピーする瞬間**に毎回やり直す。SPA の遷移や再描画に追従するため、
  ページ側の監視は要らない
- `innerHTML` は使わない（Trusted Types 対策）。UI は Shadow DOM に入れ、サイトの CSS に
  影響されない。ボタンが消されたら作り直す
- ドラッグは Pointer Events。6px 以上動いたらドラッグ、未満はタップとみなす。
  ボタンに `touch-action: none` を付けてあるので、指でドラッグしてもページはスクロールしない。
  ドラッグ直後の `click` は無視する（動かしただけでコピーが走らない）
- 位置は**画面に対する割合**で `localStorage`（キー `tm-copy-text-position`）に保存する。
  画面の回転・サイズ変更のあとも画面内に収まる。保存できない環境では初期位置に戻るだけ
- トーストはボタンが画面の上半分にあれば下へ、下半分なら上へ、横は余白の広いほうへ出す
  （初期位置が上端に近いため、上へ出すと画面外になる）
- クリップボードは `navigator.clipboard.writeText`、使えなければ `execCommand('copy')`。
  Drive設定と本文診断はTampermonkeyのメニューから使える。
  `@grant` の追加で診断用 `window.__tmCopyText` はスクリプトの分離領域にあるため、
  通常のページコンソールからは見えない場合がある。メニューの「本文抽出を診断」を使う

## 限界

- 折りたたみを開いたときに初めて中身を読み込むサイトでは、その中身は DOM に無いので取れない
- リンクだけが並ぶ「リンク集」の記事は、メニューと見分けられず自動判定では落ちることがある
  （そのときは範囲を選択してコピーする）
- コメント欄が本文のサイト（掲示板など）では、`comments` 系の class が除外される

## 診断

外れたときはTampermonkeyメニューの「本文抽出を診断」を実行する。
スクリプトの実行コンテキストを選べる環境では `window.__tmCopyText.dump()` も使える。
本文の判定方法・起点の要素・文字数と、含めた／除外した要素の理由が表で出る。
`window.__tmCopyText.extract()` はコピーせずに結果だけ返す。

```
node --check page-to-markdown.user.js

NODE_PATH=$(npm root -g) node test/page-to-markdown-drive.test.js

```

広告ブロッカーの非表示が入らない／画面外が入る／折りたたみが開いた状態で入り、
その中の広告は入らない／要素の使い回しで状態に追従する／選択範囲が優先される／

トーストが画面内に収まる／`dump()` が理由を返す）を確認する。
